## 执行裁定

- 原生 worktree 工具不能识别嵌套项目，使用项目内 Git worktree；Windows 技能脚本采用等价 ledger，保留红绿验证与提交范围。
- 核心离线锁与可选 SDK 环境分开；后续已安装实际固定 SDK并生成跨平台 requirements-live.lock。用户选择 Qwen-Plus 非思考模式＋Tavily，凭据只在本机配置。
- 冻结材料的基线调用原生 writer，比较规划/写作/证据策略；完整联网检索另列，不能宣传相同 token 预算提升。
- 未知日期允许带显式披露的事实；已知截止日后资料禁止支持当时事实。语义模型误判与建议中的隐含事实需人工核对；离线通过不能给出质量数字。
- 外部成功与本地保存之间允许重复付费窗口；已保存步骤跳过；单进程，本地评测目录也不允许并发写。
- 无证据时只允许明确未知/局限的报告；无需编造事实凑齐报告。
- 此环境无 Docker，保留打包源并披露未运行；SDK 构造和参数加载已验证，模型/搜索/TLS 实际端到端仍未验证。
- 用户已授权持续更新、维护与 GitHub 备份；在已确认的 main 基线上采用快进集成，保留全部独立提交，不 force push。连接器失败后使用常规 Git 传输，核对远端 SHA 与文档。私有 CI 日志凭据提取被自动审批拒绝，未执行；相同 pytest 入口本机复现完成诊断。

以上覆盖审查中暂未判断的行为及执行偏差，没有隐去未验证条件。后续验收包括三个真实问题、人工事实抽查及留出实验；里程碑标签在用户验收后添加。
